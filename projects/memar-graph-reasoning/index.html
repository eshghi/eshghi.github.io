Memar — Object-Oriented Architecture Studio

An AI-assisted coding tool that turns a project brief into an object-oriented architecture tree. Memar connects top-down questions, reviewed changes, and version history with a Python code notebook whose classes remain traceable to the design.

Abstract

Turning an informal software idea into a coherent architecture requires more than generating a list of classes. Requirements must be decomposed, responsibilities must be assigned to appropriate levels, and the connection between the conceptual design and the resulting code must remain visible. Memar is a coding and architecture tool that addresses this process through a hierarchical, object-oriented representation. Its objective is to connect a natural-language project brief with an inspectable goal tree, structured questioning, and a corresponding Python code skeleton.

The application first constructs an architecture and generates pseudocode with a traceable mapping between architecture nodes and code elements. A conceptual view displays the tree together with model findings and questions. A separate notebook-style view displays the complete code structure. Questioning follows a top-down order and examines each parent in relation to its direct children: whether those children are necessary, collectively sufficient, non-overlapping, and at a consistent level of abstraction. Proposed changes remain subject to user review, and accepted graph changes create versioned snapshots. Validation checks the coverage and ordering of generated classes and functions before a new result is stored.

The implemented system includes persistent projects, architecture history, node-level discussions, and a code notebook. A saved book-reservation project demonstrates the connection between a project goal, its capabilities, and the generated class hierarchy. The gallery combines English-localized views of that saved project with a direct capture from the running application. The software outcome is a working environment for reviewing and refining architecture while preserving the relationship between reasoning and code. Its contribution is the combination of controlled decomposition, scope-aware questioning, explicit change review, and traceable code generation. These mechanisms support inspection of an AI-assisted design process and help identify inconsistencies between a parent goal, the responsibilities of its children, and the structure produced for implementation.
